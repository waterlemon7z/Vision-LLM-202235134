## Project03 내 물건을 지켜줘~
 - Author : MinSeok Choi
 - Date : 2026-11-08
   
### 시나리오
1. 당신은 귀중한 물건을 두고 자리를 떠나야한다. 하지만 맡길 사람은 없다.
2. 프로그램을 실행한 뒤 카메라에 물건을 비춰 Yolo에 인식되도록한다.
3. 키보드의 S키를 눌러 경비 시작하고 녹음을 통해 보호할 물건을 등록한다.
4. "물병하고 마우스 지켜줘"
5. 잘 등록되었다면 물병과 마우스는 카메라의 집중감시가 있을 것이다.
6. 만약 카메라의 시야에서 벗어나게 되면 경보음이 나온다
7. 키보드 F키를 눌러 경비를 중단할 수 있다.

### Project Structure
 - main.py - 프로그램의 기본 흐름을 정의하고 하위 class 관리 및 실행
   - src/audio_system.py - 녹음과 stt, tts를 실행하고 관리
   - src/guard_display.py - gui에 현재 상태를 표시
   - src/local_llm.py - Gemma4의 모델 관리와 프롬프트 입력
   - src/local_yolo.py - Yolo 모델 불러오기 및 탐지

### How to run
``` bash
python3 main.py # Project03 폴더 내에서
python3 main.py non-jetson # 젯슨 이외의 환경
``` 
 - 실행 중에 S키를 누르고 지켜야 할 물건을 말로 지시하면 경비가 시작됩니다.
 - F키를 누르면 경비/경보음이 해제 됩니다.

### 창의성 및 확장성
#### 아이디어
Gemma4와 같은 로컬 LLM으로 어떤 걸 할 수 있을까 고민하다가, 내 물건을 대신 지켜주면 어떨까 해서 만들어 봤습니다.
잠깐 자리를 비울 때 카메라에 물건을 비추고 "물병하고 마우스 지켜줘"라고 말하면 경비를 시작하는 시나리오입니다.
인터넷 없이 Jetson에서 음성 인식과 물체 감시를 처리하는 것을 목표로 했습니다.   
또한 로컬의 장점이 인터넷 없이 에어갭 환경에서 가능하기에 대기업이나 기밀 문서가 있는 곳에서 해킹에 대한 걱정을 원천차단 가능할 것 같습니다.

#### 어떻게 구현

##### YOLO — 물체 탐지와 감시

OpenCV로 카메라의 frame을 받아 **YOLO11n**으로 물체의 클래스, 위치, 인식률을 구합니다.
이후 **ByteTrack**으로 이전 frame의 물체와 현재 물체를 연결해 추적 ID를 유지합니다.
같은 종류의 물건이 여러 개 있어도 ID를 기준으로 각각 관리하며, 3초 동안 확인된 물체를 대상 목록에 등록합니다.
등록 전에는 0.5초까지의 탐지 누락을 허용해 잠깐 인식되지 않았다고 바로 후보에서 제거하지 않도록 했습니다.

Gemma4가 선택한 클래스에 해당하는 물체를 모두 보호 대상으로 잠그고, 마지막으로 탐지된 시간을 계속 갱신합니다.
보호 객체가 하나라도 3초 동안 보이지 않으면 전체 보호를 종료하고 경보음을 반복 재생합니다.
F키로 경보를 정지할 수 있으며, 화면에는 보호 객체의 영문 클래스와 한국어 이름, 현재 상태를 표시합니다.

##### Whisper / Piper — 음성 입력과 안내

S키를 누르면 마이크로 **5초 동안 음성**을 녹음하고, 저장한 WAV 파일을 **whisper모델**에 전달합니다.
한국어로 인식하도록 설정해 "물병하고 마우스 지켜줘" 같은 발화를 텍스트로 변환합니다.
인식 결과에서 **끝** 같은 비음성 표지를 제거하고, 내용이 없는 결과는 Gemma4에 전달하지 않습니다.

보호 시작과 중지 등의 안내 문장은 **Piper의 한국어 TTS 모델**로 음성 파일을 생성해 스피커로 재생합니다.
녹음과 STT는 작업 스레드에서 실행하고, TTS는 별도 작업 스레드에서 생성부터 재생까지 순서대로 처리합니다.
경보음도 별도 스레드에서 반복 재생해 음성 처리가 끝날 때까지 카메라 루프가 기다리지 않도록 했습니다.

##### Gemma4 — 한국어 명령과 탐지 클래스 연결

모델은 프로그램 시작 시 한 번 불러오고, 요청할 때마다 재사용합니다. (1회만 불러옴)
YOLO에서 확인된 영문 클래스 목록에서 중복을 제거하고, Whisper가 인식한 한국어 문장과 함께 전달합니다.

프롬프트에는 보호 요청과 제외 표현을 구분하고, 탐지 목록 안에서만 대상을 선택하도록 지시했습니다.
예를 들어 `"물병과 마우스는 지켜주고 컵은 빼줘"`라는 요청에 `bottle`, `mouse`, `cup`이 탐지되어 있다면 `{"bottle":"물병","mouse":"마우스"}` 형태의 결과를 기대합니다.
JSON 스키마로 출력 형식을 제한하고, 반환된 키가 전달한 클래스 목록에 포함되는지도 코드에서 검사합니다.
선택 결과가 비어 있으면 보호를 시작하지 않고, 대상이 있으면 현재 화면에도 존재하는지 확인한 뒤 추적 ID에 연결합니다.

Gemma4 추론은 STT가 끝난 뒤 스레드에서 순차 실행하며, 메인 루프는 완료된 결과만 가져와 반영합니다.

#### 확장성
물건이 사라진 시점의 이미지와 시간을 저장하면, 나중에 "내가 없는 동안 무슨 일 있었어?"라고 물어보는 기능으로 확장할 수 있습니다.
단순히 화면에서 사라졌는지만 보는 대신 이동 방향과 위치를 함께 확인하면, 잠깐 가려진 상황과 실제 반출을 구분하는 데 도움이 될 것입니다.
또한 YOLO가 인식하지 못하는 물건을 추가 학습하거나, 물건이 사라졌을 때 휴대폰으로 알림을 보내는 기능이나 실제 경비를 호출하는 기능으로도 확장이 가능합니다.

#### 한계
 - Yolo의 인식으로부터 시작하는 프로그램인 만큼, yolo의 인식 성능에 기능 전반의 성능을 가릅니다.
 - 부족한 하드웨어 성능 때문에 낮은 성능의 llm을 사용해야하며 원하는 결과가 안나올 때가 있습니다.
 - 물체가 일정 거리 이상 이동한 경우에 대한 처리가 없습니다.

#### Gemma4 Input 예제

**1. 보호 대상과 제외 대상을 함께 말한 경우**

입력:

```json
{
  "detected_classes": ["bottle", "mouse", "cup", "person"],
  "user_utterance": "물병하고 마우스는 지켜주고 컵은 괜찮아"
}
```

기대 출력:

```json
{"bottle": "물병", "mouse": "마우스"}
```

컵은 제외 요청이 있으므로 선택하지 않고, 사람은 보호를 요청하지 않았으므로 선택하지 않습니다.

**2. 요청한 물건 중 일부만 탐지된 경우**

입력:

```json
{
  "detected_classes": ["laptop", "cup"],
  "user_utterance": "노트북이랑 지갑을 지켜줘"
}
```

기대 출력:

```json
{"laptop": "노트북"}
```

지갑은 탐지 목록에 없으므로 생략하고, 다른 물체로 대체하지 않도록 지시합니다.

**3. 보호 요청이 없는 경우**

입력:

```json
{
  "detected_classes": ["chair", "book"],
  "user_utterance": "안녕하세요"
}
```

기대 출력:

```json
{}
```

빈 결과이면 새 보호를 시작하지 않습니다. 모델이 항상 정확히 출력하지 않습니다.
